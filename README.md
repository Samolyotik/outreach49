# bridge49

Управление рассылкой через **49 TGR-аккаунтов Radar**.

Это самостоятельная замена контрольного контура `tgradar-outreach`: тот же
мост в PostgreSQL Radar, но без локальных TDLib-гейтвеев, релизных пинов,
аттестаций и хэш-проверок. Один SQLite-файл состояния, тринадцать модулей,
~3600 строк вместо 334 000.

```
план  →  очередь  →  мост Radar  →  Telegram  →  ответы  →  менеджер
```

Radar остаётся единственным владельцем сессий, прокси и необратимых RPC.
bridge49 только ставит команды и читает результат.

---

## Быстрый старт

```bash
cd /opt/outreach49

# 1. Всё ли на месте: конфиг, реквизиты, связь с Radar, реестр аккаунтов
bin/bridge49 doctor

# 2. Демо-данные — пять контактов, шаблон и две кампании
bin/bridge49 demo

# 3. Посмотреть план: кто, кому, когда и каким аккаунтом
bin/bridge49 plan cmp_demo_dryrun

# 4. Сохранить план
bin/bridge49 plan cmp_demo_dryrun --apply

# 5. Предпросмотр выпуска. Ничего не уходит — боевой режим выключен
bin/bridge49 dispatch
```

Демо-кампания `cmp_demo_dryrun` использует действие `command_dry_run`, которое
**вообще не обращается к Telegram**. Её можно провести до конца и увидеть весь
путь, ничего не задев.

## Своя кампания за пять команд

```bash
# Контакты из CSV: колонки username, name, company, segment — остальные
# колонки станут переменными шаблона
bin/bridge49 contacts --import leads.csv

# Текст. {name}, {company} и любая колонка CSV подставляются автоматически
bin/bridge49 templates --add "Первое касание" --body письмо.txt

# Кампания
bin/bridge49 campaigns --add "Стройка, июль" \
    --action send_private_dm --template t_xxxxx --segment stroyka

# План — сначала посмотреть, потом сохранить
bin/bridge49 plan cmp_xxxxx
bin/bridge49 plan cmp_xxxxx --apply

# Запустить кампанию и выпускать созревшие задачи
bin/bridge49 campaigns --status-of cmp_xxxxx --set-status active
bin/bridge49 dispatch
```

Пока не выполнены `arm on` и `dispatch --confirm`, последняя команда только
показывает, что **было бы** отправлено.

## Ежедневный цикл

```bash
bin/bridge49 dispatch --confirm   # выпустить созревшие задачи
bin/bridge49 poll                 # забрать результаты и входящие
bin/bridge49 handoffs             # что ждёт живого человека
bin/bridge49 status               # общая картина
```

Эти четыре команды удобно повесить в cron или systemd-таймер — примеры лежат
в `systemd/`.

Веб-панель (только чтение):

```bash
bin/bridge49 serve
ssh -L 8649:127.0.0.1:8649 root@сервер   # и открыть http://localhost:8649
```

## Все команды

| Команда | Что делает |
|---|---|
| `doctor` | проверка конфигурации, реквизитов и связи с Radar |
| `status` | сводка: аккаунты, контакты, задачи, ожидающие менеджера |
| `accounts` | реестр 49 аккаунтов; `--sync`, `--pause`, `--resume` |
| `actions` | справочник: какие действия бывают и какие роли их могут |
| `contacts` | `--add`, `--import`, `--opt-out`, список |
| `templates` | `--add`, `--show`, список |
| `campaigns` | `--add`, `--status-of … --set-status`, список |
| `plan` | разложить кампанию по аккаунтам и времени (`--apply` — сохранить) |
| `queue` | очередь задач с состояниями |
| `dispatch` | выпустить созревшие задачи (нужны `arm on` + `--confirm`) |
| `arm on\|off` | включить или выключить боевой режим |
| `poll` | забрать результаты команд и входящие сообщения |
| `threads`, `thread` | диалоги |
| `inbox` | последние входящие |
| `handoffs` | очередь менеджера: `--take`, `--close` |
| `events` | журнал: кто что сделал |
| `serve` | веб-панель только для чтения |
| `demo` | засеять демо-данные |

## Безопасность в двух словах

Ничего не уходит в Telegram, пока одновременно не выполнено **три** условия:

1. существует файл `var/ARMED` (`bridge49 arm on`);
2. у команды `dispatch` стоит `--confirm`;
3. кампания в статусе `active`.

Плюс к этому Radar проверяет всё заново со своей стороны и темпирует выпуск.
Подробности — [docs/SAFETY.md](docs/SAFETY.md).

⚠️ **Темп нельзя ослабить конфигом.** Рабочие дефолты — 12 видимых действий на
аккаунт в сутки, пауза 900 с плюс случайная добавка, окно 10:00–20:00 Пн–Пт.
`var/limits.json` может делать эти значения строже, но не мягче: всё, что ниже
жёсткого пола (40 / 300 с / батч 50 / окно 8:00–22:00), зажимается при загрузке,
и `bridge49 doctor` показывает каждую поправку. Пауза проверяется ещё раз перед
каждой отправкой, поэтому задачи, попавшие в базу мимо планировщика, всё равно
не уедут залпом.

⚠️ **Про `mode=immediate`.** У всех 49 аккаунтов включён
`allow_immediate_visible_actions`, поэтому команда в режиме `immediate`
исполняется почти сразу после постановки. Режим по умолчанию — `lottery`,
и менять его без необходимости не нужно.
