# Песочница автоответов — `/opt/outreach49-lab`

Вторая папка того же контура на `89.127.200.148`. Нужна, чтобы двое правили
код одновременно и не мешали друг другу: в песочнице живёт работа над
**движком автоответов**, в боевой папке — всё остальное.

Боевая переписка при этом видна целиком: боевая база открыта на чтение, и
смотреть в неё можно сколько угодно.

---

## Две папки

| | `/opt/outreach49` (боевая) | `/opt/outreach49-lab` (песочница) |
|---|---|---|
| откуда код | `rsync` с Mac Андрея | `git pull` из `/opt/outreach49.git` |
| база | своя, живая | своя копия, обновляется командой |
| отправки | идут людям | **нет** (нет файла `var/ARMED`) |
| таймеры | 9 штук, работают | **нет ни одного**, всё руками |
| кто правит | Андрей | коллега |

Копия базы — не перестраховка. Два процесса на одном файле `bridge49.sqlite`
означают две отправки одному человеку: `autoreply run` кладёт задачу, а боевой
`dispatch` её выпускает, не зная, кто её положил.

---

## Первый запуск

```bash
sudo /opt/outreach49-lab/tools/install-lab.sh
```

Дальше пять команд доступны из любого места:

| команда | что делает |
|---|---|
| `o49lab <...>` | тот же CLI, но в песочнице: своя база, отправок нет |
| `o49live <...>` | тот же CLI по **боевой** базе, только чтение |
| `o49sql [запрос]` | прямой SQL по боевой базе (`--lab` — по своей копии) |
| `o49refresh` | обновить копию базы в песочнице из боевой |
| `o49test [модуль]` | тесты песочницы |

### Примеры

```bash
o49refresh
```

```bash
o49lab autoreply run --limit 3 --hold
```

```bash
o49live threads --limit 20
```

```bash
o49sql "select at, kind, detail from events where kind like 'autoreply.%' order by id desc limit 20"
```

`--hold` в песочнице необязателен — без `var/ARMED` ничего не уедет в любом
случае, — но с ним видно, что именно поставилось в очередь.

Три мелочи, на которых легко споткнуться:

* **`o49live status` показывает «боевой режим выключен».** Он читает флаг
  `var/ARMED` из песочницы, а базу — боевую. Про боевой контур эта строка
  ничего не говорит;
* **решения движка в `events` пишутся под actor'ом `cli`**, если разбор
  запущен руками, и `autoreply` — если таймером. Отбирать надо по `kind`, а
  не по актору;
* **выпуск одноразовых ссылок StartBot в песочнице выключен.** Это внешнее
  действие с настоящим следом, тестовый прогон сжигал бы живые ссылки.
  Согласие при этом всё равно записывается, а ответ обещает ссылку отдельным
  письмом — ровно как в бою, когда выпуск не удался. Демо-маршрут работает
  целиком: у него внешнего выпуска нет. Нужен настоящий выпуск на один запуск:

```bash
O49LAB_STARTBOT=1 o49lab invites process --limit 1
```

## Как ходят правки

Обмен через голый репозиторий `/opt/outreach49.git` на том же боксе. Ничего
кроме ssh не нужно.

```
Mac Андрея  ──push main──▶  /opt/outreach49.git  ◀──push lab──  песочница
     │                                                              │
     └──rsync──▶ /opt/outreach49 (боевая)          git pull ────────┘
```

**В песочнице** — работа идёт в ветке `lab`:

```bash
cd /opt/outreach49-lab && git add -A && git commit -m "что сделано" && git push
```

Подтянуть свежий `main` к себе:

```bash
cd /opt/outreach49-lab && git pull --rebase origin main
```

**На Mac** — забрать работу песочницы:

```bash
git fetch box && git merge box/lab
```

Выкатывает в бой всегда Андрей, из `main`, после своих тестов. Песочница на
боевую папку не деплоит — иначе половина изменений уезжала бы людям
непроверенной.

## Кто чей файл

Граница проходит по смыслу: **движок отвечает «что сказать», остальной контур —
«кому, когда и что с этим сделать»**. Проверено по импортам: движок не
обращается наружу ни разу, а контур зовёт из него ровно четыре имени
(`decide_inbound_reply`, `normalize_text`, `inbound_language_reason`,
`non_silent_boundary_reply`).

### Движок — зона коллеги

| файл | что в нём |
|---|---|
| `bridge49/presales_v2.py` | промпт, контракт ответа, hard-валидация, ремонтная попытка |
| `bridge49/inbound_decision.py` | ход целиком: префильтр → промпт → модель → нормализация |
| `bridge49/policy.py` | детерминированный префильтр: опт-аут, жёсткий негатив, язык, спам |
| `bridge49/presales_context.py` | сборка `conversation_context` для промпта |
| `bridge49/truth_pack.py` | загрузка и проверка фактов |
| `bridge49/llm.py` | вызов модели, чистка стиля, guardrails |
| `bridge49/knowledge.py` | инертен: нужен только ради `KnowledgeChunk` в `llm.py` |
| `scripts/codex_llm_wrapper.py` | обёртка: `--output-schema`, enum сфер, ретраи, прокси |
| `knowledge_base/` | факты, которые видит модель |
| `tests/test_presales_v2*.py`, `test_inbound_decision.py`, `test_silent_refusal.py`, `test_runtime_facts_manager.py` | их сторожа |

### Контур — зона Андрея

`autoreply.py`, `direct_invite.py`, `replies.py`, `dispatcher.py`, `store.py`,
`planner.py`, `forum.py`, `pollers.py`, `radar.py`, `dialogs.py`,
`first_touch.py`, `outreach_texts.py`, `contact_fit.py`, `research.py`,
`catalog.py`, `watchdog.py`, `web.py`, `config.py`, `cli.py`, `deployment/`,
`systemd/`, остальные тесты.

### Правим чужое — предупреждаем

Это разрешено и иногда неизбежно. Правило одно: **сказать другому и написать
в коммите, что и зачем тронуто в чужой зоне.** Git смёржит без конфликта, а
вот сломанное ожидание не смёржится.

Два файла на стыке, где предупреждать нужно всегда:

* **`bridge49/autoreply.py`** — зона Андрея, но `demo_route_applies` и
  `manager_card_reason` читают поля контракта движка. Меняется набор или
  смысл полей — меняется и он;
* **`deployment/sector-catalog.json`** — зона Андрея (оттуда же берутся
  `demo_bot_link` и признак `ready` для выдачи), но формулировки строк —
  описания, синонимы, самоназвания, разграничители — зона коллеги.

Обязательные поля решения и то, кто их читает, — в
[ENGINE_CONTRACT.md](ENGINE_CONTRACT.md). Это единственный документ, который
нужно держать в голове при правке чужого.

## Что есть в базе

Порядок величин на 07.08.2026 — числа растут каждый день, свежие печатает
`o49refresh`:

| | сколько |
|---|---|
| входящих от Radar (`inbound`) | ~317 |
| переписки (`history`) | 1663, из них 728 входящих |
| диалогов (`threads`) | ~2861 |
| решений движка (`events`) | ~197: 86 ответ, 41 пауза, 37 ответ+менеджер, 12 hold_for_review, 9 спам, 13 срывов |
| отправленных автоответов (`tasks`) | ~130 |
| карточек менеджеру (`handoffs`) | 170 |
| выданных ссылок StartBot (`direct_invites`) | 18 |
| выданных демо-ссылок (`demo_invites`) | **0** |

Два предупреждения к этим числам:

* **Демо-маршрут ни разу не срабатывал в бою.** Ветка «сфера названа, готовой
  тестовой группы нет → ссылка на общий демо-бот» написана и покрыта тестами,
  но живых примеров у неё нет. Проверять её придётся на подстроенных диалогах;
* **Тел промптов и ответов модели нигде не сохраняется.** В журнале
  `codex_llm_usage.jsonl` (794 записи) только хэши, тайминги и вердикты —
  `prompt_sha256`, `result_json_sha256`. Повторить старый ход по журналу
  нельзя, каждый прогон — настоящий вызов модели. Если понадобится
  офлайн-повтор записанного ответа, запись тел добавляется в обёртку.

## Чего делать не надо

Три договорённости, и каждая — про одно и то же: не отправить человеку лишнего.

* **не создавать `var/ARMED` в песочнице.** Это единственный выключатель между
  «поставили в очередь» и «уехало людям»;
* **не заводить в песочнице systemd-таймеры.** Два планировщика на один контур
  дают два ответа одному человеку — на этом контур уже обжигался;
* **пишущие команды — только по своей базе.** Задача, попавшая в боевую
  очередь из песочницы, будет выпущена боевым `dispatch` как обычная, и
  человек получит второй ответ на то же сообщение. `o49live` поэтому пускает
  только чтение.
