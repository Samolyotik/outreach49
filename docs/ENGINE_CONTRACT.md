# Контракт движка автоответов

Единственная граница между движком и остальным контуром:

```python
decide_inbound_reply(context: Mapping) -> dict
```

Функция ничего не читает и не пишет в базу: на вход словарь, на выход решение.
Всё, что происходит с решением дальше — очередь, темп, карточка менеджеру,
выдача ссылок, отправка, — снаружи, в `bridge49/autoreply.py`.

Документ нужен для одного: **менять поля решения можно, но молча нельзя.**
Ниже — что читает потребитель и чем оборачивается пропажа каждого поля.

Кто какие файлы правит — в [LAB.md](LAB.md).

---

## Вердикты

`decision` — единственное поле, по которому потребитель ветвится. Движок
возвращает `action`, нормализация переводит его в `decision`:

| `action` модели | `decision` | что делает контур |
|---|---|---|
| `reply` | `auto_reply` | ставит ответ в очередь |
| `reply_and_pause` | `pause_conversation` | ставит ответ, диалог → `awaiting` |
| `pause` | `pause_conversation` | **молчит**, диалог → `awaiting` |
| `reply_and_handoff` | `reply_and_handoff` | ставит ответ и, если повод настоящий, заводит карточку |
| `handoff` | `manager_handoff` | молчит, карточка менеджеру |
| `ignore` | `ignore` | спаму молчит, остальному — короткая вежливая рамка |
| `opt_out` | `opt_out` | закрывает контакт, молчит совсем |
| `knowledge_gap` | `knowledge_gap` | шлёт `KNOWLEDGE_GAP_REPLY`, карточка менеджеру |
| — | `hold_for_review` | контракт сорвался: молчит, карточка менеджеру |

`hold_for_review` — не решение модели, а результат неудачной hard-валидации
после всех попыток. Молчание плюс человек: ошибиться в сторону карточки
дешевле, чем в сторону тишины.

Новый вердикт добавлять можно, но `ENGINE_DECISIONS` в `autoreply.py` держит
полный словарь именно затем, чтобы незнакомое имя ломалось громко, а не
превращалось в тихий отказ.

## Поля, на которых стоит поведение контура

| поле | кто читает | что будет, если пропадёт или соврёт |
|---|---|---|
| `decision` | `apply()` целиком | ход разбирается не той веткой |
| `reply_text` | очередь ответов | пусто при `auto_reply` — человек не получает ничего |
| `intent` | `apply()` при `ignore` | `spam` молчит, остальное получает вежливую рамку |
| `handoff_kind` | `manager_card_reason` | `manager_action` → карточка; `free_test_access` → выдача; `none` → ничего. Пустое значение вместе с `handoff_required` читается как срабатывание префильтра (резкий отказ или жалоба) |
| `matched_direct_invite_sector_id` | `direct_invite.record_consent` | пусто ⟹ `BranchInactive`: согласие не записывается, обещанная ссылка не выпускается никогда |
| `client_sector_text` | `demo_route_applies` | без него демо-маршрут не включается вовсе |
| `sector_confidence` | `demo_route_applies` | демо даётся только при `none`. При `likely`/`ambiguous` человек со сферой, у которой готовая группа ЕСТЬ, получил бы общий демо-бот |
| `canonical_sector_id` | `record_demo_invite` | различает «сферу не опознали» и «опознали, группы нет» в отчётах |
| `collected_fields_update` | память диалога | сфера спрашивается заново каждый ход |
| `validation_warnings` | `review_mark` | ответ уходит без пометки на перечитывание |
| `risk_level` | `review_mark` | то же для рискованных тем |
| `knowledge_gap`, `reason` | заметка карточки | менеджер видит карточку без объяснения |
| `send_allowed`, `technical_failure` | журнал и сторожа | срыв контракта выглядит как нормальный ход |

Остальные ключи payload (`version`, `mode`, `decision_key`, `provider_id`,
`inbound_id`, `account_id`, `role`, `handoff_id`, `engine`, `prompt_sha256`,
`truth_pack_sha256`, `confidence`, `semantic_intent`, `handoff_required`,
`handoff_reason`, `primary_llm_attempts`) идут в журнал и отчёты; поведение
контура на них не стоит.

## Три места, где схема обязана совпадать буква в букву

Одно и то же поле описано в трёх файлах, и разойтись им нельзя:

1. `PRESALES_V2_REQUIRED_FIELDS` в `presales_v2.py` — что проверяет валидация;
2. блок `properties` там же — форма ответа, которую модель копирует;
3. `native_output_schema` в `scripts/codex_llm_wrapper.py` — `--output-schema`,
   который отдаётся модели жёстко.

Ночью на 06.08 списки разошлись на три поля сопоставления сферы. Валидация
ждала их, схема не требовала, модель не вернула — весь ход упал в
`technical_failure`, а он молчит по замыслу. Человек согласился на тест и не
получил ничего.

Сторож: `tests/test_presales_v2_schema_parity.py`. Меняете поля — правьте все
три места одним коммитом.

⚠️ **`canonical_sector_id` в схеме обёртки — это `enum`**, собранный из
`conversation_context.sector_matching_catalog`. Пустой словарь даёт enum из
одной пустой строки, то есть модель физически не может назвать сферу, и
никакой промпт этого не исправит. Словарь приезжает из
`deployment/sector-catalog.json` через `OUTREACH_SECTOR_CATALOG`.

## Решения владельца, зашитые в поведение

Это не техника, а политика — менять только по согласованию.

* **Прямой отказ уходит в тишину.** `intent=soft_negative` обязан быть
  `action=pause` с пустым `reply_text`. Раньше требовался `reply_and_pause`, и
  06.08 человек, написавший «не планирую использовать сторонние сервисы,
  спасибо за предложение», получил в ответ «Понял, спасибо за ответ.». После
  «нет» это лишний ход.
* **Молчать нельзя, когда что-то осталось должны.** `action=pause` с пунктом
  хода в статусе `clarification_requested`, `action_required` или
  `needs_manager` валится в `hold_for_review` — то есть уходит к человеку, а не
  в тихий обрыв разговора.
* **Незнакомая сфера — не повод звать менеджера.** Сфера с готовой тестовой
  группой получает одноразовую ссылку StartBot, любая другая — ссылку на
  бессрочный демо-бот, и её дописывает контур сам, без участия модели.
* **Список поводов для `manager_action` закрыт:** живой человек, созвон,
  встреча, договор, счёт, оплата, индивидуальная цена или условия, юридический
  и персонально-данный вопрос, жалоба, спор о согласии. Не понимаете разговор —
  это `knowledge_gap`, а не менеджер.

## Пять регрессий, которые стоит держать в живых

Каждая куплена живым разговором. Если правка возвращает одно из этих
поведений — это не упрощение, это откат.

| что было | чем лечится |
|---|---|
| «Понял, спасибо» в ответ на прямой отказ (06.08) | `soft_negative` → `pause`, пустой текст |
| модель трижды не взяла демо-правило из промпта (@Anrri21) | маршрут решается кодом в `demo_route_applies`, не промптом |
| сфера `logistics_ved_china` была в сыром ответе и не доехала до выдачи (@cargo316k_1688, 04.08) | `matched_direct_invite_sector_id` в payload решения |
| подтверждённая сфера и ни одной ссылки (@secivn, 06.08) | непустой `OUTREACH_SECTOR_CATALOG`: enum схемы собирается из него |
| три поля из семнадцати пропали, ход упал молча (ночь на 06.08) | ремонтная попытка называет пропавшие ключи поимённо |
